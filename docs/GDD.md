## 1. 游戏概述

### 1.1 一句话定位
一款 2D 休闲「破坏 + 挂机」游戏：**手动砸楼赚金币 → 升级 → 解锁自动轰炸炮台 → 自动化替代手动 → 越玩越省力**。

### 1.2 目标玩家
- 泛休闲 / 碎片化玩家：一次 1–3 分钟，看重"马上有反馈、随时能放下"。
- 放置类玩家：享受"挂机回来变强"的长期养成。
- （求职定位）作为验证本人"玩法—数值—落地"闭环的代表作。

### 1.3 目标体验（体验关键词，来自 EXPERIENCE.md）
1. **干脆** —— 放置即响应，爆炸即摧毁，不拖泥带水。
2. **爽** —— 震屏 + 碎屑飞散 + 碎裂，破坏反馈层层叠加。
3. **变强感** —— 升级后立刻能感知到范围/伤害/金币变化。
4. **省力/挂机变强** —— 自动化炮台逐步替代手动点击。

### 1.4 关键时刻
- **First 30s**：30 秒内理解「锤砸→赚金币→升级」，首次伤害升级目标 ≤20 秒；首炮目标为 45–90 秒，随后转向自动轰炸。
- **首炸**：第一颗炸弹必须同时给出震屏 + 方块飞散 + 碎裂，建立破坏爽感的第一印象。
- **升级后首炸**：升级爆炸范围/伤害后，下一炸要能让人主动说"变强了"。

## 2. 核心玩法循环

```
用锤子砸 → 砸毁方块 → 碎屑飞溅 → 产出金币
    ↑                                        ↓
    └──── 升级解锁炮台、强化破坏 ←──── 金币 UI / 升级面板
        └→ 炮台自动轰炸 → 抛射爆炸（更大范围破坏）
```

- **动作循环**：破坏 → 收益 → 投入升级 → 更强破坏。
- **机制循环**：手动（锤）→ 半自动（炮台辅助）→ 全自动（多炮台轰炸）。

**核心循环 = 最简可玩版本**：即使只保留"砸→金币→升级→更狠"，循环已闭合，这是 MVP 的锚点。

## 3. 核心机制

### 3.1 无限层物理级联破坏
- 建筑是无限层塔，按**列**托管（12 列 × 每列 30 块可见，共 360 块），方块默认 RigidBody2D 静态冻结。
- 任一方块被打碎 → 该列上方失去支撑的方块各自作为**独立刚体**真实下落，落到下方存活块/地面后**吸附回网格并重新冻结**。
- 某列没有方块下落中时，自动在楼顶**补层**，任意列始终维持满高（无限塔）。
- 效果：破坏是"真实物理级联"，而不是一排一起塌平，破坏反馈更有层次。

> **迭代手记（手动 → 物理级联）**
> 最早实现是"整层整体下坠 + 收拢偏移"（_descending），问题：破坏缺层次、掩盖反馈，且整层逻辑复杂易出 bug。
> 改版后"每列物理级联 + 自动补层"，用"扫描该列是否仍有下落方块"而非计数器判断补层时机——这个更稳，能容忍一列内多块同次摧毁、下落中被额外摧毁等重叠情况。这是"用更接近物理直觉的数据结构换掉笨重状态机"的一次取舍。

### 3.2 破坏方式的成长分阶（手动 → 自动化）
破坏方式不是一成不变的，而是从手动逐步滑向自动化，锤子作用随升级弱化：

| 阶段 | 破坏方式 | 玩家行为 | 锤子的角色 |
| --- | --- | --- | --- |
| 前期 | 手动锤砸 | 高频手动点击破坏 | 核心、唯一破坏手段 |
| 中期 | 解锁炸弹炮台 | 炮台自动朝建筑轰炸，局部范围破坏 | 仍有作用、开始退居辅助 |
| 后期 | 自动化升级 | 更多/更快/更强炮台，无需手动 | 弱化为过渡工具，几乎不用 |

**设计原则**：升级的长期价值 = 把"重复手动操作"替换成"更强的自动化机制"，让玩家从"越砸越累"走向"越玩越省力"。自动化**从炸弹派生**（炮台自动轰炸、自动收集等），锤子不参与后期自动化，仅作过渡工具。

> **迭代手记（确立"自动化挂机"方向）**
> 早期方案里有"手动放置炸弹 / 微策略摆放"的设计。评审后**放弃手动放置**，明确走**自动挂机**方向：破坏方式成长 = 前期手动锤 → 中期解锁炮台自动轰炸 → 后期更多/更快/更强 + 自动收集。
> 理由：与"越玩越省力"的挂机定位一致，避免"手动放置"与"自动化"两条玩法打架。这一决策同步清理了全部相关设计文档，保证设计文档与实现一致。

### 3.3 炸弹与自动炮台
- **BombLauncher（单台自动炮台）**：解锁后在场自动瞄准建筑、持续开火；LauncherManager 按等级部署多台；带待机动画（33 帧）、后坐、炮口闪光、弹道解算。
- **BombProjectile（抛射炸弹）**：沿抛物线飞向目标，命中爆炸，造成范围伤害 + 大范围级联破坏。

## 4. 系统设计

### 4.1 升级 / 技能树
- 单局升级面板：多条升级项，分路成长——锤子强化、金币倍率、爆炸范围、爆炸伤害、炮台数量/速度等。
- 各升级项有可调参数（`@export`）与公式，与文档双向同步。

### 4.2 金币经济与滚动反馈
- 破坏产出金币，金币以**滚动计数**方式增长（`SCROLL_RATE=1500/秒`），滚动时长钳制 0.12–0.45s，避免小额闪断与大额拖沓。
- **反馈取向（设计纪律）**：破坏反馈统一为"粉碎/碎屑飞溅"，**不做掉落物品**，保证破坏手感一致。

### 4.3 转生 / 永久成长（Meta 层）
- 单局结束可**转生**，用本局累计产出结算出**转生点 RP**，投入**永久技能树**（加成/机制在开局即生效），形成跨局长线成长。
- 全链路已实装：转生面板（三大方向）、RP 结算、永久加成、机制解锁、开局炮台数、二次确认、三槽位存档。
- 生涯统计：跨局累计"击破方块数量 / 总获取金币"，主菜单展示。

### 4.4 新手引导
- First 30s 动作驱动的引导，顺畅、可跳过；引导完成标记写入存档。

### 4.5 存档 / 设置 / 转场
- 三槽位 ConfigFile 存档；屏幕切场用"碎块爆散"过场过渡输入期。

## 5. 数值与经济

**核心原则：双层数值成长** —— 单局以加法为主，转生以百分比为主，两层相乘：

```
最终 = (基础 + 单局加法) × 转生永久百分比
```

这样同时保证"每个属性都能成长"与"长线平衡、避免膨胀"。关键取值（详见 Numeric_Balance.md / Growth_Model.md / Reincarnation.md）：

| 项 | 值/规则 |
| --- | --- |
| Demo 时长锚点 | 首轮 + 三次转生后的四轮工程合计 20–30 分钟；中位目标 24–26 分钟，见 Demo_Pacing.md |
| 点击 CD | 基础 0.5s（`Hammer.attack_speed`），下限 `MIN_COOLDOWN=0.30s`，避免升级后 CD 贬值无感 |
| 金币滚动 | `SCROLL_RATE=1500/秒`，单条滚动钳制 0.12–0.45s |
| 转生点 | 收益用带**边际递减**的公式（`sqrt` 类曲线），约束无限刷；首转约 1–2 RP |
| 转生基准 | `RP_GAIN_BASE` 等为可调常量，改动走"白模验证"再落地 |

> **迭代手记（数值白模验证）**
> 手感/经济敏感参数（点击 CD、转生基准）不拍脑袋改：先在 SPEC/EXPERIENCE 定节奏锚点（挡 0 TTK 甜区、锤速 Lv2 后 CD 是否顶下限贬值），再动引擎常量，最后回填实测结论（2026-08-25 记录）。这建立了"设计预期 → 改参 → 实测回填"的调参闭环（详情见 AI_Workflow 案例二）。

## 6. 美术与音效

- **方块材质**：运行时 20×20 像素材质以最近邻显示，保留玻璃、石材、砖和钢材的区分；共享调色统一工地配色，花岗岩单独压低碎纹理对比。
- **楼体体积（2026-10-13）**：正面 12 列 ×30 层逐块可拆，增加 40px 窄侧面、整栋受光、两组固定窗带、连续柱线和薄楼板。断面、侧面随真实方块塌落和销毁，不存在固定的完整外壳。玻璃位置重排，材质血量/收益和碰撞不变。详见 [Building_Depth.md](Building_Depth.md)。
- **破坏反馈**：尘土图集特效，控制在阈值内（节流）保证性能。
- **炮台/炮弹**：33 帧待机动画 + 后坐 + 炮口闪光。
- **音效**：双 BGM 循环轮播；UI/破坏/爆炸音效。
- 说明：素材为工程演示用，属计划中的美术方向示例（对策划作品集，重点在"美术需求的拆解与规划能力"）。

## 7. 性能与工程（技术为设计服务）

- Godot 4.7.2 + Jolt 物理；建筑为 360 个 RigidBody2D。
- **切场性能**：从整批同步实例化改为**分帧实例化**（每帧 24 块 × 15 批，自下而上），消除主线程冻结 →（迭代手记）共 24 块/帧自下而上生成，保证地面支撑与塌陷目标尽早可用。
- **物理回调纪律**：碰撞/爆炸回调栈内禁止同步改物理状态（会触发 flush 阶段报错），一律 `call_deferred()` 推迟到物理步后 →（迭代手记）把"重建/压实/补层"延后执行，稳定消除 `body_set_shape_disabled` 报错。
