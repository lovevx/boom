# 借鉴报告：What the Buck?!（公开设计 → boomame 方法映射）

> 仅基于 Steam / itch / Devlog / Metacritic 的**公开设计描述**提炼"方法层"，**不逆向、不抄数值**。
> 所有数值由 boomame 自行压校（见 [Numeric_Balance.md](file:///e:/godotproject/boomame/docs/Numeric_Balance.md)）。本文聚焦"它的设计为什么成立 + 我们可借鉴哪条方法"。

---

## 〇、它解决了什么（核心同构点）

What the Buck?! 是**反向增量**：不产出资源，而是**摧毁资源**。
- 用信用卡**取款**出成堆现金 → 手动/自动**砸碎**它们 → 资金上升 → 买升级 → 技能树 → 转生。
- 官方对转生的一句话定位值得细读：**"当升级变得太贵、进度慢下来，就 End Shift（转生）"**——转生不是定时器，而是"经济停滞的缓解阀"。

和 boomame 的对位：取款≈损坏后补层/敌方产出，砸钱≈拆楼，End Shift≈Reincarnation，技能树≈转生三大方向（获取金币/攻击/炮台）+ 二周目解锁"暴击"。

## 一、六条可借鉴的方法（含自压指引）

### 1. 把"升级太贵"当作转生信号，而不是固定分钟
- **方法**：转生时机由"收益增速跑不赢成本增速"触发，官方以此引导玩家感知"该转生了"。
- **落地（boomame）**：转生门槛用 `run_total_gold`（已是 [Reincarnation.md](file:///e:/godotproject/boomame/docs/Reincarnation.md) 的 `RP=floor(K·sqrt(gold/BASE))`）；UI 在接近阈值时给"还差一点"的灰锁 + 进度条，让玩家**自己判断**何时冲进。
- **自压指引**：调 `RP_GAIN_BASE`（现 300k）即可让"首转时机"整体前移/后移；不必引入"固定第 N 分钟转生"。校验法：3 局里首转应在"感到升级变贵后 2~3 分钟内"达成。

### 2. 破坏本身 = 奖励（反向循环的爽点笑在"每一下"）
- **方法**：增量游戏常规的"产出感"在反向循环里被替换成"破坏感"——碎屑、爆炸、数字爆开就是报酬，数量可以小，但**每一击都要有即时可见反馈**。
- **落地（boomame）**：已具备破碎/复杂颗粒粉碎/炸裂/慢动作（Memory P2），补强点是**任何击破都要立刻跳金币字 + HUD 徽章跳动**（已实现 GoldHUD），确保"最小可感知增量"时刻存在。
- **自压指引**：块越小，越要保证"哪怕 +1 也要蹦数字"。别让大块被多击拆时出现"中间无反馈"的空窗——每 hit 都给血量条/裂痕反馈。

### 3. 自动化"解放手"，但别抢走"亲手毁东西"的主轴
- **方法**：它的自动化是"**自动取款**（自动生成可砸对象）"，而不是"自动产钱"——玩家依然在亲手砸。这样自动化变强 = 更有得砸，而不是玩家变无关。
- **落地（boomame）**：已经一致——全自动锤、炮台 BombLauncher 产出都走"击破才掉金币"，`GoldManager` 结算在 `_shatter`。**守住约定**：任何自动手段都不得绕过"击破"直接加钱，否则反向手感崩掉。

### 4. 稀有目标打破数值单调（≈它的 Golden Bills）
- **方法**：普通循环里插入**低概率、高收益、闪亮可辨识**的目标（官方"Golden Bills: rare, shiny, highly rewarding"），制造节奏高点、给出必打动机。
- **落地（boomame）**：正好承接已有的二周目概念——把"暴击"和"稀有方块"做成一类：低概率（建议 ~1% 出现率）× 高倍收益（普通 ×10~50），出现时给足视觉/音效仪式感。
- **自压指引**：稀有目标只在"已进入自动化流畅期"后投放，避免前 5 分钟过早干扰学习曲线。出现率与倍率两个数独立调；倍率不动、只调出现率来控节奏密度。

### 5. 剪刀差成长 = 用来制造"该转生了"的推进
- **方法**：升级价格上涨曲线与收益增长曲线留出**剪刀差**，让"不转生就变慢"，驱动 End Shift。
- **落地（boomame）**：与 [Numeric_Balance](file:///e:/godotproject/boomame/docs/Numeric_Balance.md) 已定方向一致——塔的 HP 增幅 vs 玩家点击伤害增幅（未买升级）的缺口。这正是"升级太贵"信号的来源。
- **自压指引**：中期把 `hammer_damage` 每级 "+0.3" 提到 "+0.4" 等，即压缩剪刀差；想更快逼转生就拉大剪刀差。验算法见 Numeric_Balance 第八节（只动 1~2 个数）。

### 6. 大数显示与解析必须一致（防 bug）
- **方法**：数值膨胀后要用 K/M/B 简写，但它 Devlog 记录过一个真 bug：把显示文本读回导致 `120K` 变 `120`。说明"显示格式化"与"存档/结算解析"必须解耦。
- **落地（boomame）**：当前 30 分钟单局远不至于溢出，但转生永久加成会让数量级开口。**建议尽早**引入统一大数格式化（K/M/B → 科学计数兜底），并让存档保存**原始数值**、显示只做展示映射，杜绝"读回文字"。
- **自压指引**：不需要为 Demo 做大数类（float 够 1.8e308），但接口上让金币走"单点累计"，避免任何把格式化字符串当数值解析的回读路径。

## 二、映射到 boomame 各系统的落地清单

| 借鉴方法 | boomame 现状 | 建议动作（仅方法，无具体数值） |
| --- | --- | --- |
| 转生信号 | Reincarnation 门槛式（`sqrt(gold/BASE)`） | 保留；加"接近阈值灰锁/进度提示"（升级面板或转生按钮） |
| 破坏即奖励 | shatter/炸裂/慢动作/金币跳字已有 | 补齐"多击中的每击反馈"（裂痕递增），避免击破前空窗 |
| 自动化不抢主轴 | 全自动锤/炮台均走击破结算 | 守住"自动不得绕过击破直接加钱"约定 |
| 稀有目标 | 二周目"暴击"概念 | 把它做成"低概率×高倍金 + 高辨识度"的稀有目标（~1%/×10~50 自压） |
| 剪刀差成长 | Numeric_Balance 第五/六节已定 | 支持；转生信号 = 剪刀差拉大 |
| 大数格式一致 | 无专门处理 | 存档存原始值、显示仅做展示映射；Demo 可不做大数类 |

## 三、明确排除项（不做）

- ❌ 不逆向 `.pck`/读取该游戏内部数值（无版权风险、且违背你的选择）。
- ❌ 不逐格照抄它的成本/费用表（数值由 boomame 自压，保持作品原创）。
- ❌ 不照搬它的主题/叙事（我们做拆楼，不另起"破产/取款"），只借鉴结构。
