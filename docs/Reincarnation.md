# 转生系统（Reincarnation）

> 单局升级保持现状（开局清零）；转生在核心循环之上叠加一层 meta 进度：清空本局进度 → 换取永久加成 → 下一局带着加成开局。给玩家长期目标，解决"单局爽完就归零"的留存问题。

## 一、设计目标

| 目标 | 说明 |
| --- | --- |
| 单局升级不变 | `UpgradeManager` 现有的锤子/金币/炸弹分支升级全部保持单局生效，转生后清零，玩法循环不被破坏 |
| 永久加成层 | 转生获得永久货币（转生点），点亮跨局保留的永久技能树；节点按"获取金币 / 攻击 / 炮台"三大方向组织，对全局数值、开局起始、解锁内容三方面叠加加成 |
| 长期目标 | 玩家有"为了下一局更强"的转生动机，而不是只盯着本局金币 |
| 本地存档 | 永久进度持久化到本地，重启游戏保留 |

## 二、核心概念

| 概念 | 说明 |
| --- | --- |
| 单局进度 | 本局的金币、`UpgradeManager` 各升级等级、`GoldManager.destroyed_count`。转生后全部清零（沿用现有 `reset()`） |
| 转生点（RP） | 永久货币，转生时按本局进度阶梯发放。永久持有，不随转生清零 |
| 永久技能树 | 跨局保留的加成节点，用 RP 点亮。点亮状态持久化 |
| 永久加成 | 已点亮节点提供的加成，每局开局自动生效（叠加到 `UpgradeManager` 派生数值上） |
| 转生次数 | 累计转生次数，永久保留，用于解锁型节点的门槛判定 |

## 三、转生入口与触发

- **触发方式**：随时手动转生，无硬门槛（玩家可在任意进度点转生）
- **入口位置**：升级面板顶部新增"转生"按钮（与"重新开始"并列，但视觉区隔——转生是正向 meta 行为，重新开始是回测用）
- **二次确认框**：必须显示以下信息，玩家确认后才执行
  - 本局累计金币 / 预计获得 RP
  - 当前 RP 余额 + 转生后余额
  - 已点亮永久节点数
  - 提示"本局所有金币与升级将被清零，永久加成保留"
- **进度不足保护**：本局累计金币 < `MIN_RUN_GOLD_FOR_GAIN`（推荐 10 000）时，确认框显示"转生无收益（进度不足）"，仍允许转生但发放 0 RP（给玩家后悔/重开的自由，但不奖励浅转）

## 四、转生点收益曲线（按进度阶梯）

**设计原则**：浅转收益低、深转收益高（鼓励挖深单局），但 `sqrt` 天然边际递减防止无限刷。

### 公式

```
gain_rp = floor( RP_GAIN_K * sqrt( run_total_gold / RP_GAIN_BASE ) )
```

- `run_total_gold`：本局累计产出的金币（含已花掉的，不是当前余额——用新增字段 `lifetime_gold_this_run` 累计，转生时清零）
- 推荐参数（均可 `@export` 暴露）：

| 参数 | 推荐值 | 说明 |
| --- | --- | --- |
| `RP_GAIN_K` | 1.0 | 收益缩放系数，越大每次转生得点越多 |
| `RP_GAIN_BASE` | 300 000 | 基准金币（**当前生效值**；长线未缩档时可回退 1 000 000），30 万金币对应 1 RP |
| `MIN_RUN_GOLD_FOR_GAIN` | 10 000 | 低于此值转生得 0 RP |

### 收益参考表（K=1.0, BASE=300 000，当前生效值）

| 本局累计金币 | 获得 RP |
| --- | --- |
| 1 万 | 0（进度不足） |
| 10 万 | 0 |
| 30 万 | 1 |
| 120 万 | 2 |
| 270 万 | 3 |
| 750 万 | 5 |
| 3000 万 | 10 |
| 10 亿 | 57 |

> 调参指引：若玩家普遍在 150 万金币时就能"挂机到不想挂"，可把 `RP_GAIN_BASE` 调到 150 万，让转生点更早入手；反之觉得发得太快就调大 `BASE` 或调小 `K`。

## 五、永久技能树：三大方向

> 转生点（RP）的消费出口 = 永久技能树。节点按**主题方向**组织成三条成长线，引导玩家想清楚"每局想往哪个方向变强"：
> - **方向① 获取金币** —— 决定每局能攒多少金币（买单局升级 / 触发转生）
> - **方向② 攻击** —— 削弱建筑效率（含**基础数值提升**与**百分比提升**两类）
> - **方向③ 炮台** —— 自动化主导（**数量升级 / 伤害升级 / 机制升级**）
> - **双树数值原则** —— 单局技能树（`UpgradePanel`）与转生技能树**都必须含数值提升节**：单局以加法（+X/Lv）为主、转生以百分比（+X%）为主；两者不得退化成纯"解锁型/机制型"节点而丢弃数值成长
>
> 所有节点遵循 [Growth_Model.md](file:///e:/godotproject/boomame/docs/Growth_Model.md) 双层公式：**同方向同类用加法累加**成该属性的转生乘和/加和，再与单局层相乘。数值为暂定档，实装时按 Numeric_Balance 的 30 分钟节奏微调。

### 方向① 获取金币（经济成长线）

| 类别 | 节点 | 成本（RP） | 效果 | 上限 |
| --- | --- | --- | --- | --- |
| 百分比提升 | 金币之心 I / II / III | 1 / 2 / 3 | 金币产出 +50% / +100% / +150%（入 coin_multiplier 转生乘和，点满 ×2.5） | 3 级 |
| 基础数值提升 | 初始资金 I / II / III | 1 / 2 / 3 | 开局送 500 / 1 500 / 3 000 金币 | 3 级 |
| 基础数值提升 | 击破金币 I / II | 1 / 2 | 单块击破基础金币 +1 / +2（入加法括号，作用于 BuildingBlock 击破产出基底） | 2 级 |

### 方向② 攻击（削弱建筑效率）

> 分两类：**基础数值提升**（开局自带攻击底子）+ **百分比提升**（跨局永久倍数）。

**基础数值提升（开局生效）**

> 不做"开局自带升级等级"（Lv.1/Lv.2），改为扁平**基础加值**（基础伤害 +X）；攻速只保留百分比（疾风之势），不做基础数值提升。

| 类别 | 节点 | 成本（RP） | 效果 | 上限 |
| --- | --- | --- | --- | --- |
| 基础数值提升 | 基础伤害 I / II | 1 / 2 | 点击基础伤害 +1 / +2（入加法括号） | 2 级 |
| 基础数值提升 | 初始熟练 I | 1 | 开局自带"全自动锤" | 1 级 |

**百分比提升（永久倍数）**

| 类别 | 节点 | 成本（RP） | 效果 | 上限 |
| --- | --- | --- | --- | --- |
| 百分比提升 | 破坏之力 I / II / III | 1 / 2 / 3 | 锤子伤害 +5% / +10% / +15%（转生乘和） | 3 级 |
| 百分比提升 | 疾风之势 I / II | 1 / 2 | 锤子攻速 +10% / +20%（转生乘和） | 2 级 |
| 基础数值提升 | 巨人之力 I / II | 1 / 2 | 锤子范围 +14px / +28px（加法进括号，每级 = 单局单级 7px 的 2 倍） | 2 级 |
| 百分比提升 | 重力加速 I / II | 1 / 2 | 建筑下落速度 +10% / +20%（转生乘和） | 2 级 |

### 方向③ 炮台（自动化主导）

> 按解锁方式分两类：**数量升级**与**机制升级**以转生次数达标后自动解锁（不花 RP）；**伤害升级**与**基础数值提升**用 RP 点亮。

**数量升级（转生次数门槛）**

| 节点 | 解锁条件 | 效果 |
| --- | --- | --- |
| 炮台数量扩展 | 转生 ≥ 1 / 2 / 3 / 4 次 | 开局自带炮台 1 / 2 / 3 / 4 台。**单局升级面板的"解锁炮台"仅保留 Lv.0→1（解锁第一台，保 MVP 首局体验）**；Lv.2/3/4 数量由本节点永久接管，`reset()` 时按转生次数设置开局炮台等级 |

**基础数值提升（RP 购买）**

| 类别 | 节点 | 成本（RP） | 效果 | 上限 |
| --- | --- | --- | --- | --- |
| 基础数值提升 | 炮塔基础伤害 I / II | 1 / 2 | 炸弹基础伤害 +3 / +6（加法进括号，作用于 BOMB_DAMAGES 表值） | 2 级 |

**伤害升级（RP 购买）**

| 类别 | 节点 | 成本（RP） | 效果 | 上限 |
| --- | --- | --- | --- | --- |
| 百分比提升 | 弹药强化 I / II / III | 1 / 2 / 3 | 炸弹伤害 +15% / +30% / +45%（转生乘和，作用于 BOMB_DAMAGES 表值） | 3 级 |
| 百分比提升 | 爆裂范围 I / II | 1 / 2 | 爆炸半径 +15% / +30%（转生乘和，作用于 BOMB_RADII 表值） | 2 级 |

**机制升级（转生次数门槛）**

| 解锁内容 | 门槛 | 说明 |
| --- | --- | --- |
| 暴击系统 | ≥ 1 次 | 单局技能树新增"暴击率 / 暴击伤害"升级项；方块受击时按暴击率判定 ×暴击伤害 |
| 连锁伤害加成 | ≥ 2 次 | 爆炸对范围内的存留方块额外触发连锁伤害（已有连锁倒塌的数值强化） |
| 第二炮台类型：散射炮 | ≥ 3 次 | 解锁散射炮（单台向多方向抛射），与原抛射炮并存，单局可升级 |

> 各方向的具体数值待实装时按 Numeric_Balance 逐项定档，本文档只锁"方向 / 节点 / 门槛与倍率量级"。

## 六、本地存档

- **存储方式**：Godot `ConfigFile`，每槽位一个文件 `user://save_slot_{0,1,2}.cfg`（共 3 个互相独立的完整存档槽）
- **负责模块**：`SaveManager`（autoload 单例）统一读写；`ReincarnationManager` 只暴露状态与结算方法，不再自带持久化
- **每槽位保存内容**（完整独立存档）：
  - 转生 meta：`reincarnation_points`（当前 RP 余额）、`total_reincarnations`（累计转生次数）、`permanent_nodes`（永久节点点亮状态，如 `{"coin_heart": 3, ...}`）
  - 单局进度：`gold.total`（当前金币）、`gold.lifetime`（本局累计金币）、`gold.destroyed`（累计摧毁数）、`upgrades.levels`（全部升级等级）
- **读取时机**：主菜单点击某槽位「继续」时由 `SaveManager.load_slot()` 恢复；无存档时点击=开始新游戏
- **写入时机**：局内 HUD「存档」按钮、返回主菜单前自动落盘、转生结算后落盘"新开局"、点亮/升级永久节点后自动落盘
- **存档损坏兜底**：读取失败时回退到默认初始状态（不崩溃）；旧版 `reincarnation_save.cfg` 首次启动自动迁移进槽位 0

## 八、数值边界（已同步进 SPEC.md / Numeric_Balance.md）

| 参数 | 推荐值 | 说明 |
| --- | --- | --- |
| `RP_GAIN_K` | 1.0 | 转生点收益缩放 |
| `RP_GAIN_BASE` | 300 000（当前生效值；未缩档长线可回退 1 000 000，见 Numeric_Balance.md） | 基准金币；与"从1起步"缩档后的单局量级匹配，让首次转生 ~18 分钟够得到 2~3 RP |
| `MIN_RUN_GOLD_FOR_GAIN` | 10 000 | 低于此值转生得 0 RP |
| 永久节点单级成本上限 | 3 RP | 控制单节点不超贵 |
| 永久技能树总成本上限 | 约 30 RP | 全点亮所需 RP（控制 meta 进度总长度） |

## 九、Non-goals（明确不做）

- 不做云端存档 / 跨设备同步
- 不做转生排行榜
- 不做转生过场动画（先用确认框，后续 P3 再考虑）
- 不做转生奖励皮肤/主题替换
- 不做"转生次数本身作为数值倍率"（次数只用于解锁门槛，不直接加数值，避免数值膨胀）
- 不做转生重置永久进度的"硬重置"按钮（永久进度一旦获得不可逆，防止误操作）
