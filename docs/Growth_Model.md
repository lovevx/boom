# 数值增长模型（Growth Model）

> 整个游戏的数值增长统一由"加法（基础数值）"与"乘法（百分比）"两种形式构成。加法做早期线性爽感，乘法做后期指数爆炸，两层叠加形成 S 形数值曲线。本文档确立公式与属性分类，供 `UpgradeManager` / `ReincarnationManager` 实装时遵循。

## 一、设计目标

| 目标 | 说明 |
| --- | --- |
| 双形式并存 | 数值增长同时包含加法（基础数值）与乘法（百分比），而非只用一种 |
| 分层分工 | 单局层以加法为主（线性进度感，每局重置），转生层以乘法为主（指数累积，永久叠加） |
| 不互相稀释 | 加法不与乘法直接相加，避免乘法被加法稀释或被无脑堆叠 |
| S 形曲线 | 早期加法主导（线性爽）、中期叠加（加速）、后期乘法主导（指数爆炸） |
| 可平衡 | 所有增长通过"加和/乘和"叠加，设上限防通胀，调参点集中 |

## 二、两种增长形式

| 形式 | 术语 | 表现 | 适合层 | 适合属性 |
| --- | --- | --- | --- | --- |
| 加法增长 | 基础数值 | 每级 +固定值，收益线性 | 单局层为主 | 绝对值属性、倍率属性的早期 |
| 乘法增长 | 百分比 | 每级 ×(1+百分比)，收益指数 | 转生层为主 | 倍率属性的后期、meta 加成 |

> 关键原则：**同层同类增长用加法累加，跨层用乘法叠加**。即同一层内多个"伤害+5%"节点相加成一个"乘和"，再与另一层相乘。这样乘法层数固定为两层（单局层 × 转生层），不会无限叠乘失控。

## 三、数值属性分类

游戏所有可成长数值归为三类，每类有固定的最终值公式。

### A 类：倍率属性（base = 1.0，最终输出为倍率）

代表：锤子速度、锤子伤害、金币倍率、建筑下落速度。

```
最终值 = 基础值 × (1 + 单局加和) × (1 + 转生乘和)
       = 1.0 × (1 + Σ单局加法) × (1 + Σ转生百分比)
```

- 单局层：加法累加到单局加和（如锤子伤害每级 +0.3，Lv.3 时单局加和 = 0.9）
- 转生层：百分比累加到转生乘和（如破坏之力 Lv.2 +10%，转生乘和 = 0.10）
- 同类转生节点之间相加（破坏之力 I+II+III 全点亮 = +5%+10%+15% = 30%，作为伤害转生乘和 0.30）

**举例（锤子伤害，单局 Lv.3 + 转生破坏之力 Lv.2）**：
`1.0 × (1 + 0.9) × (1 + 0.10) = 1.0 × 1.9 × 1.10 = 2.09`

### B 类：绝对值属性（base = 起始值，最终输出为绝对值）

代表：锤子范围、炸弹伤害、炸弹范围。

```
最终值 = (基础值 + 单局加和 + 转生加和) × (1 + 转生乘和)
```

- 单局层：加法累加（如锤子范围每级 +7px）
- 转生层：既可加法（如范围拓展 +20px），也可乘法（如"范围 +5%"节点）
- 转生加法进括号内，转生乘法在括号外

**举例（锤子范围，单局 Lv.2 + 转生范围拓展 Lv.1 +20px）**：
`(0 + 80 + 20) × (1 + 0) = 100px`

### C 类：离散/表驱动属性（base = 表值，最终输出为表值或表值组合）

代表：炮台数量、炸弹速率（冷却倍率）。

```
最终值 = 表值（由等级索引）；跨层组合时按"转生解锁数量 × 单局倍率"组合
```

- 炮台数量：单局表 [0,1]（仅解锁第一台），转生解锁 2/3/4 台 → 开局数量 = 转生解锁数
- 炸弹速率：单局表 [1.0, 0.85, 0.72, 0.62, 0.53]（冷却倍率），最终冷却 = 基础冷却 × 速率倍率
- 这类属性不套双层公式，按表驱动 + 转生门槛组合

## 四、S 形数值曲线

| 阶段 | 主导 | 表现 |
| --- | --- | --- |
| 早期（单局低 Lv，0~1 次转生） | 加法 | 每级提升固定，线性爽感，玩家感受"变强" |
| 中期（单局满级，1~3 次转生） | 加法×乘法叠加 | 两层开始叠加，加速明显 |
| 后期（多转生） | 乘法 | 转生乘和累积，数值指数爆炸，meta 进度感 |

调参指引：若后期数值膨胀过快，调低转生乘法节点百分比或下调 RP 收益；若后期乏力，调高转生乘法上限或新增乘法节点。

## 五、数值平衡与防通胀

| 原则 | 说明 |
| --- | --- |
| 跨层才相乘 | 只有"单局层 × 转生层"两层数相乘，同层同类相加，避免无限叠乘 |
| 转生乘和设上限 | 每个属性的转生乘和上限建议 ≤ 5.0（即最终倍率 ≤ 6×），防数值失控 |
| 加法与乘法不直接相加 | 禁止 `最终 = 基础 + 单局加和 + 转生乘和` 这种稀释乘法的写法 |
| 基础值固定 | 所有增长通过加和/乘和叠加，基础值不随等级变，便于平衡与重置 |
| 单局加和上限 | 单局加和由单局升级满级决定，天然有上限（每局重置） |

| 炮台数量 | C 离散 | 0 | 表 [0,1]（单局仅解锁第一台） | 转生 1/2/3/4 次解锁 1/2/3/4 台 | 开局数量 = 转生解锁数 |

## 七、落地接入点（不写实现，只标"在哪改"）

| 模块 | 接入点 | 改动方向 |
| --- | --- | --- |
| `UpgradeManager.gd` | 各属性 getter 末尾 | A 类 getter 返回 `1.0 × (1 + 单局加和) × (1 + ReincarnationManager.get_mult_sum(属性))`；B 类返回 `(基础 + 单局加和 + 转生加和) × (1 + 转生乘和)`；C 类保持表驱动 |
| `ReincarnationManager.gd`（新增） | 提供 `get_mult_sum(attr)` / `get_add_sum(attr)` | 返回指定属性的转生乘和 / 转生加和（按已点亮永久节点累加） |
| `BuildingBlock.gd`（金币产出） | 读取 `coin_multiplier` | 无需改，`coin_multiplier` 已是应用公式后的最终倍率 |
| `Hammer.gd` / `BombProjectile.gd` | 读取 `hammer_damage` / `bomb_damage` 等 | 无需改，读到的已是最终值 |
| `UpgradePanel.gd` | 升级项显示文案 | 显示"当前加法 +X / 转生乘法 +Y%"，让玩家看到两层增长 |

## 八、Non-goals

- 不做三层及以上乘法叠加（只固定单局层 × 转生层两层，防失控）
- 不做"基础值随等级变化"的设计（基础值固定，增长只通过加和/乘和）
- 不做动态难度缩放（数值增长只升不降，不因玩家变强而自动调高敌人）
- 不做加法与乘法的混合累加（禁止 `基础 + 加和 + 乘和`，会稀释乘法）
- 不在本模型引入暴击/连击等新机制（这些由 Reincarnation.md 方向③·机制升级单独解锁后再定档）
