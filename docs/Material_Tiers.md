# 材质阶梯（Material Tiers）—— 累计摧毁数驱动的变强曲线

> 设计 + 实现规格。目标：把"升级变强"从看不见的数值，变成看得见的**材质阶梯**——
> 楼越砸越高级（石膏→大理石→红砖→花岗岩；普通玻璃→浮法玻璃→钢化玻璃），材质序列以**莫氏硬度**为设计基准，
> 让中后期挂机有"社区越拆越高级"的成长叙事。

## 一、设计意图

现有无限塔每次补层用的都是固定材料（默认挡 0：墙 HP 5 / 窗 2 / 楼板 7，见
[BuildingSetup.gd](file:///e:/godotproject/boomame/scripts/BuildingSetup.gd#L21-L46)）。
问题：玩家升级后，塔毫无反馈，变强只能靠数字（伤害/金币）感知，缺少"拆的东西变高级"的直观爽点。

本方案用**可读的材质阶梯**补上这一层：随着玩家累计摧毁方块变多，**新生成的**建筑部件逐档升级，
更硬、也产出更多金币。既给变强一个可见锚点，也让收益曲线随进度滚起来。

## 二、核心原则（不可违反）

### 2.1 塔的材质升级必须**严格滞后**于玩家战力

塔升档是"**越拉越开但总能翻过去的那堵墙**"，绝不是和玩家 DPS 对撞。
如果每升一档就把 HP 抬到恰好抵消玩家升级伤害，"解锁炮台 → 明显变强"就消失了，
变成一潭死水——这正是 [EXPERIENCE.md](file:///e:/godotproject/boomame/docs/EXPERIENCE.md) 明文的核心禁区「升级无感」。

判定标准：**玩家在升到下一档后，破一座同规模的楼仍然比上一档更快**，只是"效率增速"放缓。

### 2.2 升档是正向奖励，不是惩罚

更高级 ≠ 只更硬。**更高级的方块更值钱**（单块金币更高），
保证中后期挂机收益持续增长，而不是用更硬同时更穷来拖慢玩家。

### 2.3 只作用于"新生成"的方块，旧塔不升

已经被摧毁后**重新补层**的方块才使用新挡位材质。仍在场上的存活方块保持砸它时的材质。
这样玩家能亲眼看到"剩余旧楼 + 补出的新楼"混搭，叙事看得见。

## 三、进度源：累计摧毁数（cumulative destroyed count）

- **定义**：自开局（或最近一次"重新开始"）以来，玩家/炮台累计**彻底摧毁**的方块总数。
- **为什么用它**：原生挂机计进度，无需 UI、无需新"关卡"概念，天然契合自动化方向。
- **存放位置**：现有全局单例 [GoldManager.gd](file:///e:/godotproject/boomame/scripts/GoldManager.gd)（它已是 BuildingBlock 依赖的全局进度单例，且已有 `reset()` 供"重新开始"归零）。
- **递增时机**：每块方块 `_shatter()` 被彻底摧毁时 +1，与"产出金币"同一位置。

### 4.4 莫氏硬度 → 数值设计规则

材质序列以**莫氏硬度**为设计基准，落到方块数值上遵循三条规则：

1. **同角色内，硬度越高越靠后**：墙按 石膏(1.5-2) → 大理石(3-4) → 红砖(4-5) → 花岗岩(6-7) 升序排挡；
   楼板按 石灰石(2-3) → 混凝土(4.5-5.5) → 瓷砖(6-8) → 淬火钢(7-8) 升序排挡，HP 随挡位抬升。
2. **角色修正优先于裸硬度**：窗永远是全场最脆（HP 2~5）。
   玻璃莫氏硬度虽高（5.5-7），但作为"窗"厚度极薄、抗冲击差，因此按薄脆修正压低 HP——
   且 **HP 只由玻璃材质区分**（普通 2 / 浮法 3 / 钢化 5），同材质各挡位血量恒定，
   正合"钢化玻璃只是抗冲击提升，莫氏硬度不变"的说明（不同玻璃靠抗冲击拉开，挡位只换玻璃类型与金币）。
3. **升档是正向奖励**：更高级更值钱（金币随挡位上涨），呼应 2.2，不用"更硬更穷"拖慢玩家。

> 不建议按纯硬度对全体方块排序——那会让"窗"变坦克、楼板失去结构厚实感，且破坏现有 HP 平衡曲线
> （5→7→9→12 / 2→3→5→5 / 7→9→12→16，随"从1起步"缩档）。

## 五、文件级改动清单

### 5.1 [GoldManager.gd](file:///e:/godotproject/boomame/scripts/GoldManager.gd)

新增累计摧毁数计数器：

```gdscript
var destroyed_count: int = 0   # 累计摧毁方块数（驱动材质挡位）

func get_destroyed_count() -> int:
    return destroyed_count

func register_destroyed() -> void:
    destroyed_count += 1
```

`reset()` 追加一行清零（"重新开始"回到挡 0）：

```gdscript
func reset() -> void:
    total_gold = 0
    destroyed_count = 0
    gold_changed.emit(0)
```

### 5.2 [BuildingBlock.gd](file:///e:/godotproject/boomame/scripts/BuildingBlock.gd)

在 `_shatter()` 里、`_spawn_gold()` 之前，登记一次摧毁：

```gdscript
func _shatter() -> void:
    shattered.emit()
    GoldManager.register_destroyed()   # 每毁一块 → 累计摧毁数 +1（驱动材质挡位）
    # …… 原有 debris / _spawn_gold / queue_free 不变
```

> 金币产出逻辑不改：`_spawn_gold()` 仍用 `gold_value × coin_multiplier`，
> 挡位带来的单块金币上涨已由 `gold_value` 承载（5.3）。

### 5.3 [BuildingSetup.gd](file:///e:/godotproject/boomame/scripts/BuildingSetup.gd)

这是主改动点，替换"固定墙/窗/楼板配置"为"挡位驱动配置"：

1. **替换** `TYPE_COLORS` / `TYPE_HP`：改为 `TIERS` 挡位表（结构见 4.2/4.3），
   每个部件条目追加 `material`（材料名，供 HUD/日志展示，不参与数值）。
   类型字符映射：`"#"→wall`、`"W"→window`、`"="→floor`。
2. **替换** `_gold_value_for(type)`：金币直接改为从挡位表读取（去掉旧 4/6/7 写死，也无需额外的 `gold_mult`）。
3. `_spawn_block()` 里读取当前挡位并应用：

   ```gdscript
   func _spawn_block(col, level, type, is_floor) -> BuildingBlock:
       var tier := _current_tier()
       var entry := TIERS[tier][_type_key(type)]
       # block.hp = max_hp = entry.hp
       # block.gold_value = entry.gold
       # sprite.modulate = _tint_by_hp(entry.color, entry.hp, jitter)
   ```

4. 新增挡位解析：

   ```gdscript
   # 由累计摧毁数反查当前挡位（默认挡 0）
   func _current_tier() -> int:
       var n := GoldManager.get_destroyed_count()
       for i in range(TIERS.size() - 1, -1, -1):
           if n >= TIERS[i].threshold:
               return i
       return 0
   ```

5. 初始 `_generate()` 与 `reset()` 无需单独改：
   - 开局 `destroyed_count == 0` → 挡 0。
   - `reset()` 已让 GoldManager 清零 → 重建后也是挡 0。

> `_random_layer_pattern`（墙层满墙 / 2~4 窗）与 `_refill_type` 的**结构逻辑不改**，
> 只改"这个格子生成后用什么材质/HP/金币"。

## 六、边界与规则（实现时守住）

- **旧塔不升档**：只在补层/生成新方块时读取 `_current_tier()`；已存活方块不回溯。
- **挡位不随"正在下落的方块"升级**：下落中的方块算旧，补层的新块才用新挡。
- **重新开始**：GoldManager.reset() 清零 destroyed_count → 回到挡 0，与旧逻辑完全一致。
- **性能**：`_current_tier()` 每生成一块方块调一次，只是读整数 + 4 次比较，可忽略；在任何列补层前批量算一次缓存更优，但非必须。
- **避免阻挡 First-30s**：挡 0 是全场最脆（石膏/普通玻璃），首次解锁炮台验证不受影响，反而更爽。
- **窗 HP 材质决定**：`_spawn_block` 对玻璃材质从 `GLASS_BASE_HP` 取 HP（普通 2 / 浮法 3 / 钢化 5），非玻璃走挡位表 `hp`；挡位表 `window.hp` 仅为展示/兜底，改玻璃血量统一改 `GLASS_BASE_HP`。

## 十一、特殊材料（暂不进主曲线）

莫氏硬度表里另有 4 种材料不适合进主材质阶梯，各自的处理意见：

| 材料 | 莫氏硬度 | 建筑用途 | 处理建议 |
| --- | --- | --- | --- |
| 普通低碳钢材 | 4-5 | 主体结构、梁柱骨架 | 可做"结构骨架"特殊块（需新增第 4 个角色 + 生成逻辑），暂缓 |
| 人造石英石 | 6-7 | 厨房台面、装饰面板 | 可做楼板高档变体，随附送 |
| 氧化铝耐磨陶瓷 | 8-9 | 特殊耐磨构件 | 罕见特殊块 / 挑战块，普通建筑极少使用 |
| 金刚石 | 10 | 钻头、切割磨片 | 不作为建筑构件，留给"加工工具"设定，不入方块 |

> 决策口径：主曲线只放"普通建筑"级建材；"建筑主体较少使用"与"不作为建筑构件"的材料一律进不了主曲线。
