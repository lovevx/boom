# MainMenu.md —— 主界面构思

> 主界面 = 游戏启动的第一屏，玩家进入破坏玩法前的"门面"。
> 本文件先定义「有什么、为什么有、怎么接」，实现时按此落地。

## 一、定位与目标

- **定位**：作为 `run/main_scene` 的启动场景，点击「开始游戏」才进入主玩法 `Main.tscn`。
- **目标 1（入口）**：让玩家明确"这是游戏、怎么开始"，一秒内找到主操作。
- **目标 2（预告）**：用最少的文字让玩家在进游戏前就建立核心循环预期：**砸/炸 → 赚金币 → 升级 → 解锁炮台自动化**，服务 MVP 的 First 30s 验证目标。
- **调性**：与玩法一致——**干脆、爽**。不做花哨入场、不做复杂粒子、不做音乐（沿用 Non-goals）。

## 二、界面布局（1920x1080）

```
┌────────────────────────────────────────────────────┐
│                                                    │
│          ◤ 楼体剪影背景（静态，位于主界面底层） ◢   │
│                                                    │
│              ＢＯＯＭＡＭＥ                        │  ← 标题区
│         锤子砸楼 · 炸弹轰鸣 · 越砸越省力            │  ← 副标语
│                                                    │
│                                                    │
│            ┌─────────────────────┐                 │
│            │     开 始 游 戏      │                 │  ← 主 CTA（唯一大按钮）
│            └─────────────────────┘                 │
│                                                    │
│              [ 玩法说明 ]   [ 退出游戏 ]            │  ← 次要操作
│                                                    │
└────────────────────────────────────────────────────┘
```

> 玩法说明（4 格循环图）不常驻主界面，收进「玩法说明」弹出面板（见第五节）。

## 三、内容元素（每个都要有理由，不堆砌）

| 元素 | 形态 | 为什么有 |
| --- | --- | --- |
| **标题区** | 游戏名大标题 + 一句副标语 | 建立品牌与"拆楼"主题的第一印象；副标语一句话把玩法定位讲清楚 |
| **玩法说明（4 格循环图）** | 图标+短文案：🛠砸楼 → 🪙赚币 → ⬆升级 → 💣自动炸 | 进游戏前先预告成长路径，配合 Onboarding 让 First 30s 更好达成；只在主界面给"简版"，细节引导仍由游戏内 Onboarding 承担 |
| **开始游戏（主 CTA）** | 居中、最大、唯一主按钮 | 主操作必须只有一个，杜绝犹豫；点击 = 全新一局 |
| **玩法说明按钮** | 次要按钮 | 重复查看说明的入口；MVP 可弹出与 4 格图同内容的小面板，或直接省略（4 格图已常驻在主界面） |
| **退出游戏** | 次要按钮，桌面端必须 | 桌面端基本操作；Non-goals 不做设置/成就，但退出必须有 |

> 说明：MVP 无存档（Non-goal），故**不做**"继续游戏 / 读档"；只做"开始游戏 = 全新一局"。

## 四、交互流程

```
启动 → MainMenu（主界面）
   │
   ├─ 点击「开始游戏」→ 重置游戏状态 → 切换到 Main.tscn（全新一局）
   ├─ 点击「玩法说明」→ 弹出说明面板（4 格循环图，可关闭）
   └─ 点击「退出游戏」→ get_tree().quit()
```

## 五、与现有系统的衔接（关键）

- **场景**：新建 `scenes/MainMenu.tscn`，`project.godot` 的 `run/main_scene` 改指向它。
- **状态重置**：`GoldManager` / `UpgradeManager` 是常驻 Autoload。从主界面进游戏前必须走一次现有 reset() 流程（GoldManager.reset + UpgradeManager.reset），保证每次"开始游戏"都是空金币 + 全零升级 + 满楼的全新一局；楼体与残留清理由进入 Main 后 Building / in_game_entity 组自处理。
- **依赖单向**：MainMenu 只负责"启动 + 切换"，不反向依赖玩法逻辑；复用 Autoload 的公开 reset 接口即可，不深挖各模块内部。
- **返回主菜单**：MVP 阶段**不做**（游戏内已有"重新开始"按钮足够回测）；若做，注意同样要先走 reset，且需在 MainMenu 与 Main 之间约定切换回主界面后是否清空 Autoload 状态。

## 六、MVP 边界 / 明确不做

- ❌ 不做存档 / 继续游戏 / 读档（Non-goal）
- ❌ 不做设置界面（音量 / 画质，Non-goal）
- ❌ 不做成就 / 统计 / 皮肤（Non-goal）
- ❌ 不做音乐 / 音效、复杂动态背景、粒子入场特效（Non-goal；保持"干脆"）
- ❌ 不做游戏内"返回主菜单"按钮（MVP 用现有"重新开始"即可）

## 七、已确认的决策

| 取舍点 | 决策 | 说明 |
| --- | --- | --- |
| 背景 | 静态楼体剪影 | 简单几何拼楼作为主界面底层背景，贴合拆楼主题、零成本 |
| 玩法说明位置 | 收进弹出面板 | 不常驻主界面，点击「玩法说明」按钮弹出 |
| 玩法说明按钮 | 保留 | 玩家随时可重复查看，成本低 |
| 启动场景 | MainMenu 启动 | `run/main_scene` 改为 MainMenu.tscn |

## 八、测试目标

- 启动即见主界面（标题 + 楼体剪影背景），点击「开始游戏」1 秒内进入玩法且为全新一局（金币 0、无炮台、满楼）。
- 从主界面进游戏后，核心循环能在 First 30s 内被玩家理解（配合 Onboarding）。
- 退出按钮生效；「玩法说明」弹出面板可开可关、不阻塞主操作。
