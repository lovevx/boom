# 数值平衡文档（Numeric Balance）—— 30 分钟单局基准

> 面向"破坏方块 + 升级 + 转生"的 30 分钟纯在线单局体验，把数值语法落地为**可直接照抄跑测的基准参数**。
> 本文档**不改**材质分档表（[Material_Tiers.md](file:///e:/godotproject/boomame/docs/Material_Tiers.md)）与转生点公式（[Reincarnation.md](file:///e:/godotproject/boomame/docs/Reincarnation.md)），而是在它们之上，把"点击CD + 多方块挡位 + 击破才掉金币"三者咬合成一套完整节奏。

---

## 〇、先厘清：你的数值模型 ≠ 纯 DPS 堆叠

你的游戏有两个机制让"通用增量 DPS 公式"失效：

| 机制 | 代码事实 | 对数值模型的影响 |
| --- | --- | --- |
| 点击 CD | `Hammer.gd` `attack_speed=2.0`，`CD = 1/(attack_speed × hammer_speed)`；冷却未到本次点击不生效 | 点击是**节拍器**，玩家输出有硬频率上限 |
| 多方块挡位 | `BuildingSetup.TIERS`（墙/窗/楼板 × 4 挡），由 `destroyed_count` 驱动 | 不是"同种方块血量线性涨"，而是**分挡换皮**，每挡有自己的 TTK |
| 击破才掉金币 | `_spawn_gold()` 只在 `_shatter()` 触发 | 收入按**击破次数**结算，不是平滑 DPS |

因此本作的基准单位不是 `DPS × Time`，而是 **TTK（击破时间）**。升级的本质是"压缩 TTK"而非"调大 DPS"。所有参数都围绕这一点组织。

## 一、当前已实现的基线（不改也能跑，先读这份）

以下数字全部来自现有代码，作为数值起点。

### 1.1 方块挡位（HP / 单块金币）—— 结构角色 × 材质挡位

> 数值口径（2026-08-25 起）：整个体系从"1"起步（借鉴 What the Buck!?）。
> 基础点击伤害 = 1（约等于最脆窗户 HP 2 的三分之一）；方块 / 金币从个位数铺起。
> 窗 HP 由玻璃材质决定（普通 2 < 浮法 3 < 钢化 5，同一玻璃各挡位恒定），挡位只换玻璃类型与金币。

| 挡位 | 门槛(destroyed_count) | 墙 wall | 窗 window | 楼板 floor |
| --- | --- | --- | --- | --- |
| 0 | 0 | 5 HP / 2 币 | 2 HP / 1 币 | 7 HP / 2 币 |
| 1 | 40 | 7 / 3 | 3 / 2 | 9 / 3 |
| 2 | 120 | 9 / 4 | 5 / 3 | 12 / 5 |
| 3 | 300 | 12 / 5 | 5 / 4 | 16 / 7 |

> 挡位由"累计摧毁数"驱动、只作用于补出的新方块；更硬同时更值钱（升挡是正向奖励）。

### 1.2 点击伤害 / 点击 CD

- 基础点击伤害：`1.0`（`Hammer.hammer_damage`），实际 = `1.0 × UpgradeManager.hammer_damage`（升级 +0.3/级、转生×乘和）
- 基础 CD：`attack_speed=2.0` → **每次点击间隔 0.5s**；`hammer_speed` 升级 +0.4/级加速，CD 下限 `MIN_COOLDOWN=0.30s`

### 1.3 升级费用（加法类五项：锤速/锤伤/范围/金币倍率/下落速度）

`费用 = 2 × 1.3^level`；炸弹分支用独立费用表（首台炮台 2 / 速率 4 / 伤害 4 / 范围 4）。

### 1.4 自动炮台（自动化主产出，解锁后在场自动开火）

- 数量表 `[0,1,2,3,4]`，冷却表 `[3.0,2.5,2.0,1.6]`s × 速率倍率 `[1.0,.85,.72,.62,.53]`
- 伤害表 `[3,4,6,9,12]` × `hammer_damage`；范围表 `[80,120,160,200,240]`

### 1.5 转生

`RP = floor(1.0 × sqrt(run_total_gold / 300_000))`；`run_total_gold < 10_000` 得 0 RP。永久加成三大方向见 Reincarnation.md。

## 二、点击 CD 的定位与改造（最高优先级杠杆）

按"30 分钟节奏"体验，CD 应作为 **节奏引导器** 而非硬限制：

| CD 取向 | 取值 | 适用 | 本作的判断 |
| --- | --- | --- | --- |
| 极短 | 0.1~0.2s | 强调连点爽感，CD 仅防误触 | 会淹没"升级感" |
| **节奏** | **0.3~0.5s** | 引导关注"每次点击的质量" | ✅ **推荐的甜点区** |
| 策略 | 0.8~1.5s | 迫使 CD 间隙做升级决策 | 30 分钟内有效点击数太少 |

**现状问题**：基础 CD=2.0s 过慢——30 分钟最多 `1800/2 = 900` 次有效点击（参考模型建议 3600~6000 次），前期容错率极低、挫败感强。

**推荐改造**（✅ **已应用 2026-08-25**：`Hammer.gd` + `SPEC.md`）：
- 把 `attack_speed` 从 `0.5` 提到 `2.0` → 基础 CD = **0.5s**
- 保留 `hammer_speed` 升级（+0.4/级），但**给 CD 设下限**：`MIN_COOLDOWN = 0.30s`（对应 hammer_speed ≤ ~3.3）
- 理由：CD 一旦趋近 0，多方块挡位分层完全失效、退化为纯数值碾压。CD 下限是挡位设计的**守卫**。

> 更保守的备选：`attack_speed=1.0`（CD=1.0s，偏"策略"极）。先在 0.5s 跑通，再按 5. 节奏锚点调。

## 三、多方块挡位的教学/节奏分层

不要给每个方块做"每级血量成长"——挡位本身就是天然的教学阶梯。每挡承担一个节奏功能：

| 挡位 | 到达 | 节奏功能 | 无升级下击破所需击数(TTK@CD0.5s) |
| --- | --- | --- | --- |
| 0 | 开局 | **建立条件反射**：点击→击破→掉币 | 窗 3 击(1.5s)；墙 5 击(2.5s)；楼板 7 击(3.5s) |
| 1 | ~40 摧毁 | **数值升级可见**：伤害 Lv.1 起把多数压到可接受击数 | 窗 4 击；墙 7 击；楼板 9 击 |
| 2 | ~120 摧毁 | **真实抉择**：买伤害 or 先解锁炮台 | 窗 6 击(3.0s)；墙 9 击(4.5s)；楼板 12 击(6.0s) |
| 3 | ~300 摧毁 | **自动化主战场**：依赖炮台/范围 | 窗 8 击(4.0s)；墙 12 击(6.0s)；楼板 16 击(8.0s) |

> 基础伤害=1 时手动单块击数偏多（"从1起步"的代价），早期**尽量先买 1~2 级锤伤**把击数压下来；
> BASE_COST=2 让首段升级近乎免费，正好承接这个引导。中期起靠炮台分担——符合"自动化主线"。

**点击伤害升级的杠杆作用**（`hammer_damage` Lv.1 = ×1.3 → 1.3；Lv.2 = ×1.6）：
- 挡 0 墙 5：×1.0=5 击 → ×1.3=4 击(Lv.1) → ×1.6=3 击(Lv.2) ＝ 解锁即明显变快，制造"数值升级有体感"的正面反馈
- 挡 2 墙 9：×1.0=9 → ×1.3=7(Lv.1) → ×1.6=6(Lv.2)，伤害升级在每挡都有可感的击破次数收益

> 这就是你要的"剪刀差"：**塔的血量增幅** 与 **玩家点击伤害增幅（未买升级）** 之间的缺口。
> 不买伤害升级，挡位爬升就是天然减速带（墙 5→7→9→12 击）；但升级总能翻过去，且更高级更值钱——符合 [Material_Tiers](file:///e:/godotproject/boomame/docs/Material_Tiers.md) 的 `2.1 滞后升级` 红线。

## 四、TTK 与 CD 的黄金比例（平衡标尺）

```
理想 TTK ≈ CD × (1.5 ~ 3)
```

| TTK 与 CD 关系 | 后果 |
| --- | --- |
| TTK < CD | 点击浪费，玩家觉得"手速被系统吃掉" → 挫败 |
| TTK ≈ CD | 完美节奏但无容错，长时间累 |
| **TTK = CD×(1.5~3)** | **甜蜜区**，允许偶尔失误又紧凑 |
| TTK > CD×5 | 明显卡关，需提示升级或拉自动 |

以推荐 CD=0.5s 校验第三节：**基础伤害=1 时手动偏高**——挡 0 窗 1.5s(=3×，甜)、墙/楼板 2.5~3.5s(=5~7×，过渡偏慢)，这是"从1起步"的代价。**补上 1~2 级锤伤（BASE_COST=2 近免费）后**，挡 0 各角色回落到 2.5~4 击、即 ×3~4 合理区；T3 墙 12 击(=~6×，末期压力) 正合"逼近天花板，靠炮台收尾"的意图。

## 五、30 分钟节奏锚点（白模验证清单）

把这些时间点作为里程碑，每次调参后对照检查：**注意本作是"点击→自动化"两阶段，参考模型的前期也按此重映射**。

| 里程碑 | 目标 | 判定方式 |
| --- | --- | --- |
| 第 1 分钟 | 不看教程理解"点击=击破=金币=升级" | 玩家能否自发点向第一项升级 |
| 第 3~5 分钟 | 买到第一项升级（cost 2）并感到变快 | 击破数是否有可感提升 |
| 第 5~8 分钟 | **解锁第一台炮台**（cost 2）→ 自动化开场 | 炮台在场后金币曲线是否有台阶 |
| 第 10~15 分钟 | 挡位推进（destroyed_count →40/120），砖体变高级 | 玩家感知"拆的东西变高级了" |
| 第 18 分钟 | **首次转生窗口**（run_total_gold 是否达可获益阈值，见七） | 转生按钮可否给出"还差一点"的灰锁感 |
| 第 23 分钟 | 二周目带永久加成开局，进度领先一周目同期 | ×(1+永久乘和) 是否体感明显 |
| 第 28 分钟 | 展示完整自动化钩子 + 下一次转生 | 玩家是否有"想继续"冲动 |

## 六、升级经济标定（30 分钟内不要无限成长）

参考模型的 4 段式策略，映射到**本作已实现的升级项**（不新增项）：

| 阶段 | 优先购买的**已有**升级 | 在 TTK 上的作用 | Demo 期望 |
| --- | --- | --- | --- |
| 前期(0~5') | 锤子伤害(2) / 锤子速度(2) | 减击破次数 / 压缩 CD | 拉低 T0 各角色击数（1~2 级锤伤后 2.5~4 击） |
| 中期(5~15') | 解锁炮台(2) / 金币倍率(2) | 自动化开局 / 单块收入↑ | 与手动形成分工 |
| 后期(15~30') | 炮台伤害·速率·范围 / 全自动锤 | 自动化 DPS↑ | 满足"越玩越省力" |

**费用检查**：加法类 `2 × 1.3^n`，前 6 级为 `2/3/3/4/6/7`，覆盖整个 30 分钟的早期节奏（"从1起步"让首段升级几乎免费）；炸弹表首台 2 与"5~8 分钟解锁"的目标成本匹配，金币倍率 / 炮台升级随挡位与点数自然拉开价差。**不要引入"方块等级 50 级"等分级成长**，本作挡位已承担该节奏，擅自叠加会破坏手感。

**自动化产出量级**（作为衔接验算）：
- 手动早期：挡 0 单块 1~2 币 × 金币倍率，每次点击对应一次击破
- 自动化：单台炮天赋伤害 3 / CD 3.0s / 半径 80px ≈ 每 3s 清一片 → 转换率看实际命中数；升级后伤害 4~12 承接中后期
- **衔接断点**：手动→自动切换时，若"自动单块币 × 击破率" < 手动单点击币，玩家会感觉"挂机反而变慢"，此时应优先拉高 金币倍率 或 伤害。

## 七、转生阈值锚定（30 分钟 Demo 需"够得到"）

现有公式 `RP = floor(sqrt(run_total_gold / 3e5))` 原按 1e6 为**长线**标定：30 分钟单局通常到不了 1M 金币，首次转生往往会得 0 RP → **"转生没变强"**，正撞上节奏锚点 23 分钟。已随"从1起步"把 `RP_GAIN_BASE` 下调为 300 000（见 SPEC.md）。

> ⚠️ 这是与 [Reincarnation.md](file:///e:/godotproject/boomame/docs/Reincarnation.md) 的**潜在冲突**：其默认 `RP_GAIN_BASE=1e6` 面向多局长期，而本 30 分钟 Demo 希望首转（~18 分钟）就给 2~3 RP。

**建议（Demo 专用，需你确认后同步改 Reincarnation.md / SPEC.md）**：

| 参数 | P2 默认(长期) | Demo 建议值 | 说明 |
| --- | --- | --- | --- |
| `RP_GAIN_BASE` | 1 000 000 | **300 000** | ~40 万 → 1 RP（`sqrt(4e5/3e5)=1.15`）；~120 万 → 2 RP（`sqrt(4)=2`）；~270 万 → 3 RP |
| `MIN_RUN_GOLD_FOR_GAIN` | 10 000 | 保持（低门槛给"浅转自由"） | 不影响首转节奏 |

> 保留 `sqrt` 曲线与三大方向骨架；只调基准，让首次转生在 30 分钟内既有"够得到"又保留"深转收益更高"的递进。

## 八、调参指引（只动一两个数原则）

所有目标"改一处、验一处"，避免联动失控：

| 想调的目标 | 改哪里 | 具体建议 |
| --- | --- | --- |
| 前期太慢 / 太快 | `Hammer.gd` `attack_speed` | 0.5 → 2.0 起步；太顺→回 1.0，太卡→ 3.0 |
| 挡位减速不自然 | `BuildingSetup.TIERS[i]` 的 hp / gold | 只动"墙/楼板"的 HP 或金币，别动破坏量级 |
| 挡位爬速 | `BuildingSetup.TIERS[].threshold` | 40/120/300 整体 ×0.8 或 ×1.2 |
| 中后期被塔反超 | `hammer_damage` 每级 +0.3 | 提高到 +0.4 让更多角色 1 击 |
| 首转太快/太晚 | `RP_GAIN_BASE` | 300k 基础上：太早→调大，太晚→调小 |

> **红线**（沿用 Material_Tiers 2.1 / 8）：相邻挡位之间"破楼耗时"必须单调递减；一旦某挡打平或变长，就是升挡太急，回落 threshold 或补区段 HP。CD 不得低于 0.30s。

## 九、白模验证步骤（不回填先别动美术）

1. 改 `attack_speed` 到 2.0，去掉升级，只用基础点击打三种挡 0 方块，记录实际 TTK。
2. 校验基础 TTK 是否落在 `CD×(1.5~3)` 甜区（0.75~1.5s）。不在 → 先调 HP 或 CD，再加升级。
3. 基础节奏 OK 后，叠升级（锤伤/锤速/金币倍率），核对第三节"每挡击破次数"表。
4. 解锁第一台炮台，验算自动化开场是否优于手动（第六节衔接断点）。
5. 跑满 30 分钟，逐格回填第五节锚点；每个里程碑偏差 >2 分钟的参数标红。
6. 只重测被标记的参数，其余不动。
